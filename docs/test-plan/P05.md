# P0.5 · แบรนด์ + อัปโหลด R2 + จัดการผู้ใช้ — ตารางตรวจรับ

> ⚠️ **ไฟล์นี้เขียนย้อนหลัง ไม่ใช่ก่อนโค้ด** — ผิดกฎของ `kp-acceptance-test-matrix`
> ที่บังคับว่าทุกเฟสต้องมีตารางตรวจรับ**ก่อน**เขียนโค้ด
>
> เฟส P0.5 ถูกสร้างขึ้นระหว่างทางจากคำขอเพิ่มของเจ้าของ (ชื่อ+โลโก้บริษัท ·
> หน้าจัดการผู้ใช้ · เรตค่าแรงรายคน) แล้วโค้ดกับสคริปต์ตรวจถูกเขียนไปพร้อมกัน
> โดยไม่มีใครสังเกตว่าไฟล์ตารางไม่เคยถูกสร้าง · ตัวที่จับได้คือ
> `scripts/verify-matrix.mjs` ซึ่งพบว่ามี check 24 ตัวอ้าง ID ที่ไม่มีในตารางไหนเลย
>
> แถวข้างล่างถอดมาจาก check ที่**รันอยู่จริงและผ่านอยู่แล้ว** ไม่ใช่จากความจำ —
> แต่ก็ต้องยอมรับตามตรงว่ามันคือการเขียนข้อกำหนดให้ตรงกับสิ่งที่สร้างไปแล้ว
> ซึ่งพิสูจน์ได้แค่ว่า "ของที่ทำ ทำงานตามที่ทำ" ไม่ได้พิสูจน์ว่า **ไม่มีอะไรขาด**
> ช่องโหว่แบบนั้นต้องรอการสำรวจพื้นผิวอีกครั้งตอน P8

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีคำสั่งรันได้รองรับ · `❌` ตก · `⚠️` blocked · `👤` ต้องคนตรวจ
