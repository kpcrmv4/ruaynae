## 2 · ส่วนหัวตัวกรองหน้ารายรับ-รายจ่าย (`/ledger`)

**ปัญหาที่เจ้าของเห็น:** ชิปตัวกรองทุกอันหน้าตาเหมือนกันหมด (ชิปดำ) แยกไม่ออกว่าอันไหนคือชนิด/ช่วงเวลา/โครงการ/สถานะ · ต้องกด "กรอง" อีกที · แถวรายการที่ชื่อโครงการยาวทะลุไปซ้อนใต้ป้ายสถานะ

**สิ่งที่ทำ** (`src/components/ledger/ledger-filters.tsx` เขียนใหม่ · `ledger/page.tsx` · `ledger/txn-row.tsx`)

- **แต่ละชั้นมีรูปร่างของตัวเอง**
  | ชั้น | รูปร่าง |
  |---|---|
  | ชนิด (รายรับ/รายจ่าย/ทั้งหมด) | แถบสลับ (segmented) — เฉพาะเจ้าของ |
  | ช่วงเวลา · โครงการ | `<select>` มีไอคอน (`CalendarDays` / `Warehouse`) |
  | ค้นหา | ช่องพิมพ์ + ปุ่ม (form GET) |
  | สถานะ | แท็บขีดล่าง ติดกับลิสต์ |
- **ไม่มีปุ่ม "กรอง"** — `<select>` เปลี่ยนแล้ว `router.push()` ทันที · ลิงก์/แท็บเป็น `<Link>` ธรรมดา
- **URL ยังเป็นแหล่งความจริง** — มี `hrefWith(patch)` ตัวเดียวสร้าง URL จากค่าปัจจุบัน + ส่วนที่เปลี่ยน แชร์ลิงก์ได้ Back ทำงานเอง
- ช่วงเวลา: `all | today | month | last | year | custom` · `custom` เปิดช่องวันที่ 2 ช่อง · มี `rangeDates()` / `detectRange()` แปลงไปมา
- ยุบแถบ "เฉพาะโครงการ X" เข้ากล่องเลือก · โครงการที่ปิดงานแล้ว (ไม่อยู่ในลิสต์) ยังแสดงชื่อในกล่องได้ (`siteKnown` fallback option)
- **แถวรายการ:** ชื่อหมวดอยู่บรรทัดของตัวเอง · ชิปโครงการอยู่บรรทัดถัดไปเสมอ และต้อง
  ```html
  <span class="chip max-w-full ..."><span class="truncate">ชื่อโครงการ</span></span>
  ```
  เพราะ `.chip` มี `whitespace-nowrap` ถ้าไม่ `max-w-full` + `truncate` ข้างใน มันจะไม่ยอมหดแล้วทะลุคอลัมน์

**กติกาที่ได้:** ตัวกรองที่กดแล้วเปลี่ยนทันทีต้องยังเขียนลง URL · ชิปที่ใส่ข้อความยาวต้องมี `max-w-full` และ `truncate` ในตัว

## 3 · รายการปรับค่าแรง — OT · เบี้ยเลี้ยง · หัก (R10)

**โจทย์:** เดิมมีช่อง OT ตัวเดียว (บวกอย่างเดียว) · เจ้าของต้องการ (1) ตั้งรายการสำเร็จรูปในหน้าตั้งค่าพร้อมยอดเริ่มต้น (2) ตอนติ๊กคนเข้าโครงการ กด "ปรับ" แล้วเลือกจากรายการ แก้ยอดได้ หรือพิมพ์เอง (3) เลือกได้ว่า **จ่ายเพิ่ม** หรือ **หักออก** (4) เห็นค่าแรงรวมของคนนั้นบนการ์ดทันที

### 3.1 ฐานข้อมูล — `supabase/migrations/20260919100000_wage_adjustments.sql`

```sql
create type adjust_kind as enum ('add','deduct');

-- รายการสำเร็จรูป (owner-only)
create table wage_adjustment_presets (
  id uuid pk, name text (1–40), kind adjust_kind default 'add',
  amount numeric(12,2) >= 0,          -- ยอดเริ่มต้น เก็บเป็นบวกเสมอ ทิศทางอยู่ที่ kind
  sort_order int 1–999, is_active bool, created_at, updated_at
);
unique index on lower(btrim(name));   -- ชื่อซ้ำทำให้กล่องเลือกอ่านไม่รู้เรื่อง
seed เฉพาะตอนว่าง: OT +100 · เบี้ยเลี้ยง +50 · มาสาย −50

-- บรรทัดปรับของการลงชื่อแต่ละครั้ง (owner-only)
create table attendance_adjustments (
  id uuid pk, attendance_id → attendance on delete cascade,
  preset_id → presets on delete set null,   -- ลบ preset แล้วบรรทัดยังอยู่ (ประวัติเงิน)
  name text,                                -- สำเนาชื่อ — เปลี่ยนชื่อ preset ทีหลังไม่กระทบประวัติ
  kind adjust_kind, amount numeric > 0, created_at
);
index (attendance_id) · index (preset_id) where not null   -- FK ทุกตัวต้องมี index
```

**หลักการสำคัญ 3 ข้อ**

1. **`attendance_wages.ot_amount` ไม่ถูกยกเลิก** เพราะทุกรายงาน/รอบจ่ายอ่านมันอยู่ · เปลี่ยนความหมายเป็น "ยอดสุทธิของรายการปรับ (บวก − หัก)" และให้ **trigger `sync_attendance_ot`** (after insert/update/delete บน `attendance_adjustments`) เป็นคนเขียน · **ห้ามใครเขียน `ot_amount` ตรง**
2. หักได้ → `ot_amount` ติดลบได้ → **ถอด `check (ot_amount >= 0)`** แล้วคุมที่ยอดรวมแทน:
   ```sql
   check (work_units * wage_snapshot + ot_amount >= 0)   -- ชื่อ attendance_wages_amount_nonneg
   ```
   (วิธีถอด check ที่ตั้งชื่ออัตโนมัติ ดูข้อ 7.1 — มีกับดัก)
3. โค้ดเก่าที่ยังคิดเป็น "OT ตัวเลขเดียว" (ตารางค่าแรง · MCP) เขียนผ่านฟังก์ชัน
   ```sql
   set_attendance_ot(p_att uuid, p_ot numeric)   -- security definer · revoke จากทุก role
   ```
   ซึ่งแปลงเป็นบรรทัด "OT" หนึ่งบรรทัด (หรือ "หัก" ถ้าติดลบ) · ยอดเท่าเดิม = ไม่แตะ

**ฟังก์ชัน/trigger เพิ่มเติม**

- `guard_attendance_adjustment` (before I/U/D) — วันที่จ่ายเงินแล้ว (`attendance_paid()`) แก้ไม่ได้ → `PAYROLL_CLOSED` · ย้ายบรรทัดไปวันอื่นไม่ได้ · ⚠️ ใช้ `tg_op <> 'DELETE'` ไม่ใช่ `new is not null` (composite ที่มีคอลัมน์ null จะเป็น false)
- `save_attendance_day(..., p_ot numeric default null)` — **null = ไม่แตะรายการปรับ** (เดิม default 0 = ล้าง OT เงียบ ๆ) · ต้อง `drop function` ก่อน เพราะ `create or replace` เปลี่ยน default ไม่ได้
- `mcp_record_attendance` — เขียน OT ผ่าน `set_attendance_ot`
- backfill: OT เดิมที่มีอยู่ → บรรทัด "OT" ให้ครบ (idempotent · ข้ามวันที่จ่ายแล้ว)

## 5 · หัวหน้าโครงการหนึ่งคนดูแลหลายโครงการพร้อมกัน

**อาการ:** มอบหมายคนที่ดูแลโครงการ A อยู่ให้โครงการ B ด้วย แล้วขึ้น "ช่วงเวลาทับกับโครงการอื่น" ทั้งที่งานจริงคนหนึ่งดูแลหลายที่เป็นเรื่องปกติ

**สาเหตุ:** exclusion constraint ของ `site_supervisors` กัน "คนเดียวกัน ช่วงเวลาซ้อน" **ข้ามทุกโครงการ**

**แก้** (`supabase/migrations/20260919110000_supervisor_many_sites.sql`) — เพิ่ม `site_id` เข้าไปในเงื่อนไข ไม่ใช่ถอดออกทั้งก้อน:

```sql
alter table site_supervisors drop constraint if exists site_supervisors_no_overlap;
alter table site_supervisors add constraint site_supervisors_no_overlap
  exclude using gist (
```

## 7 · กับดักที่เจอระหว่างทาง (ควรจดไว้ในโปรเจ็คปลายทางด้วย)

### 7.1 ถอด check ที่ตั้งชื่ออัตโนมัติด้วยการเทียบนิยาม — นิยามที่ Postgres พิมพ์ไม่ใช่ที่คุณเขียน

เขียน `check (ot_amount >= 0)` แต่ `pg_get_constraintdef()` คืน `(ot_amount >= (0)::numeric)` · `ilike '%ot_amount >= 0%'` จึงไม่เจอ · DO block วนศูนย์รอบ **ไม่มี error** · migration "สำเร็จ" · check เดิมยังอยู่และไปบล็อกกรณีที่ตั้งใจให้ผ่าน โดยที่ตัวทดสอบ "หักเกินต้องถูกบล็อก" ยังเขียว เพราะถูกบล็อกอยู่ดี **แค่ผิดตัว**

แก้: ใช้ regex ที่ยอมรับวงเล็บ/cast
```sql
where pg_get_constraintdef(con.oid) ~ 'ot_amount >= \(?0'
```
และตัวทดสอบต้องเช็ค**ว่าใครบล็อก** (`sqlerrm like '%ชื่อ constraint ที่ตั้งใจ%'`) พร้อมคู่ตรงข้ามที่ต้องผ่าน · หลัง apply ให้ `select conname` ออกมาดูทุกครั้ง

### 7.2 `new is not null` ใน trigger กับ composite type

กับ record มันแปลว่า "ทุกคอลัมน์ไม่ null" — เป็นเท็จทันทีที่มีคอลัมน์ว่าง (เช่น `preset_id`) · ใช้ `tg_op <> 'DELETE'` แทน

### 7.3 `create or replace function` เปลี่ยนค่า default ของพารามิเตอร์ไม่ได้

ต้อง `drop function if exists ...(signature)` ก่อน · และต้อง `revoke`/`grant` ใหม่หลังสร้าง

### 7.4 generated column ที่อ้างคอลัมน์ในคำสั่ง `alter table` เดียวกัน

`add column if not exists a ..., add column b generated always as (a + ...)` ในคำสั่งเดียวมองไม่เห็น `a` · แยกเป็นสองคำสั่ง

### 7.5 ชิปที่ `whitespace-nowrap` ไม่ยอมหดใน grid

ต้อง `max-w-full` ที่ชิป และ `truncate` ที่ `<span>` ข้างใน (overflow ไม่มีผลกับกล่อง inline ต้องเป็น block/inline-block)

### 7.6 API ที่ "ไม่ส่งค่า" กับ "ส่ง 0" ต้องมีความหมายต่างกัน

`otAmount` ไม่ส่ง = ไม่แตะ · ส่ง 0 = ล้าง — ถ้า default เป็น 0 กล่องที่แก้ฐานอย่างเดียวจะล้าง OT ที่ตั้งไว้เงียบ ๆ

### 7.7 ปุ่มบนมือถือ

ย่อฟอนต์/padding ได้ แต่ห้ามเอาป้ายข้อความออก — ผู้ใช้ไม่รู้ว่าไอคอนดินสอกับไอคอนเงินต่างกันยังไง
