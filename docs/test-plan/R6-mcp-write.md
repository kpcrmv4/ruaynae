# R6 · ให้ตัวเชื่อม MCP บันทึกข้อมูลได้ — ตารางตรวจรับ

> คำสั่งเจ้าของ 1 ก.ย. 2569: *"อยากเพิ่มให้ mcp สามารถบันทึกข้อมูลรายรับรายจ่ายด้วยได้ไหม
> เช่นฉันอาจจะส่งสลิปหรือรูปใบทางด่วนเข้าไปในแชท เดี๋ยวบอก AI อ่านก็ถามว่าให้ช่วยบันทึก
> เป็นอะไรระหว่างรายรับหรือรายจ่าย เป็นค่าใช้จ่ายส่วนรวมหรือแยกโครงการ และสามารถบรรจุได้ว่า
> ใครเข้างานก่อสร้างไหนบ้างในวันนี้"*
>
> **ข้อตกลงที่เจ้าของเลือกไว้ (1 ก.ย. 2569):**
> 1. AI สรุปให้ดูในแชท ถ้าตอบว่าใช่ = บันทึกเป็น **`approved`** ทันที ไม่เข้าคิวอนุมัติ
> 2. **ทุกคีย์บันทึกได้** ไม่แยกใบอ่านกับใบเขียน
> 3. ขอบเขต: รายรับ-รายจ่าย · ลงชื่อคนเข้าโครงการ · เบิกล่วงหน้า · แก้/ลบรายการเดิม
> 4. ต้องมีป้าย **"บันทึกผ่าน AI"** ให้แยกออกว่าแถวไหนมาจากแชท
>
> P9 เดิมเขียนว่า "อ่านอย่างเดียว" — ตั้งแต่เฟสนี้ **ไม่จริงแล้ว**
> ดู `supabase/migrations/20260901170000_r6_mcp_write.sql` และแถว P9-PROTO-07 / P9-SEC-03 / P9-SEC-04
> ใน [`P9.md`](P9.md) ที่ความหมายเปลี่ยนไปพร้อมกัน

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีหลักฐาน · `❌` ตก · `👤` ต้องคนตรวจ (เครื่องจริง/สายตา) · `⚠️` ปิดในเฟสนี้ไม่ได้ พร้อมเหตุผล

> 👤 ของรอบนี้ = แถวที่ต้องมี **dev server + คีย์จริง + เบราว์เซอร์** — เครื่องที่ทำรอบนี้
> ไม่มี `.env.local` ของโปรเจ็คจริง (มีแต่ค่าปลอมสำหรับ `next build`) จึงรัน
> `scripts/verify-mcp-write.mjs` ไม่ได้ · แถว DB ทั้งหมดถูกตรวจ **บนฐานข้อมูลจริง**
> ด้วยธุรกรรมที่ **ย้อนกลับทั้งก้อน** (`raise exception` ปิดท้าย) ผลอยู่ในช่อง "หลักฐาน"
> · ปิดแถว 👤 ด้วย `node scripts/verify-mcp-write.mjs` บนเครื่องพัฒนา ทั้งสองธีม · 390/768/1440

> 🔴 **สิ่งที่พังแบบไม่มีอาการในเฟสนี้:**
> `auth.uid()` ที่ยังเป็น null ตอน insert → `guard_transaction` มองว่าเป็น service
> แล้ว**ข้ามการเติม `created_by`** → ได้แถวไร้เจ้าของที่ทุก policy สาขา
> `created_by = auth.uid()` ตายกับมันตลอดไป (บทเรียน P2-DB-04) ·
> โมเดลที่เรียกซ้ำเพราะไม่ได้คำตอบ → รายการเดียวกลายเป็นสองแถวยอดเท่ากันเป๊ะ ·
> `audit_log` ที่ไม่แยก "เจ้าของกดเอง" ออกจาก "AI กดแทน" → ทุกแถวอ่านว่าเจ้าของทำเอง
> เพราะฟังก์ชันสวมสิทธิ์เจ้าของจริง ๆ

## 5 · สิ่งที่ **ไม่** ทำในเฟสนี้ (และเพราะอะไร)

| เรื่อง | เหตุผล |
|---|---|
| แนบรูปสลิปเข้า R2 ผ่าน MCP | โมเดลส่งไบต์ของรูปกลับมาทาง tool call ไม่ได้ — MCP รับพารามิเตอร์เป็น JSON เท่านั้น และรูปที่ผู้ใช้แนบในแชทอยู่ฝั่งไคลเอนต์ของ AI ไม่ใช่ฝั่งเรา · ทางที่ทำได้จริงคือให้โมเดล**อ่านตัวเลขจากรูป** แล้วบันทึกเฉพาะตัวเลข ซึ่งคือสิ่งที่ทำในเฟสนี้ · คำอธิบาย tool และหน้า `/mcp` จึงบอกตรง ๆ ว่ารูปไม่ได้ถูกเก็บ แทนที่จะปล่อยให้เจ้าของเข้าใจเอาเองว่าสลิปอยู่ในระบบแล้ว |
| อนุมัติ/ตีกลับรายการของหัวหน้าโครงการผ่าน AI | เป็นการตัดสินใจที่ควรเห็นสลิปเต็ม ๆ ก่อน · คิวอนุมัติในแอปแสดงรูปให้ดูได้ แชทไม่มี |
| ปิดรอบจ่ายค่าแรงผ่าน AI | ปิดแล้วย้อนไม่ได้ และล็อกข้อมูลย้อนหลังทั้งงวด — ไม่ควรเกิดจากประโยคเดียวในแชท |
| แยกคีย์อ่านกับคีย์เขียน | เจ้าของเลือกไว้ว่าให้ทุกคีย์บันทึกได้ (1 ก.ย. 2569) · ถ้าวันหน้าอยากแยก ให้เพิ่มคอลัมน์ `can_write` ที่ `mcp_keys` แล้วเช็คใน `resolveKey()` — ไม่ต้องแตะฟังก์ชันฐานข้อมูลเลย |
