## 1 · เป้าหมายและเหตุผล

เจ้าของกิจการอยากถามคำถามที่**ไม่ซ้ำเดิม**กับข้อมูลของตัวเอง — "ไซต์ไหนกำไรบางสุด",
"เดือนนี้ค่าปูนไปเท่าไหร่", "ค้างจ่ายค่าแรงใครบ้าง" — ผ่าน Claude หรือ ChatGPT
ที่เขาใช้อยู่แล้ว โดยไม่ต้องให้เราสร้างหน้าจอใหม่ทุกครั้งที่เขามีคำถามใหม่

เราจึงเป็น **ผู้สร้างเซิร์ฟเวอร์ MCP** ไม่ใช่ผู้ใช้ — ตรงข้ามกับทุกที่ในโปรเจ็คนี้
ที่คำว่า MCP หมายถึง Supabase/Chrome MCP ที่ **เรา** ใช้ตอนพัฒนา

**ทำไมไม่ใช่หน้าจอ / ไม่ใช่ cron:** ตัวเลขที่ดูทุกวันเป็นหน้าจอ (มีแล้ว) · สรุปตามเวลา
เป็น cron (มีแล้วที่ `daily-digest`) · คำถามที่เปลี่ยนไปเรื่อย ๆ คือของที่ MCP ทำได้อย่างเดียว
· ค่าใช้จ่ายตกอยู่กับโควตา AI ของเจ้าของ ไม่ใช่ของเรา

### เกณฑ์ว่าสำเร็จ

1. เจ้าของกด "สร้างคีย์" ที่หน้า `/mcp` คัดลอก URL เดียว วางใน Claude แล้วถามคำถามได้เลย
2. ตัวเลขที่ AI ตอบ **ตรงกับตัวเลขบนหน้าจอแอปเป๊ะ ๆ ถึงสตางค์** — ไม่งั้นเจ้าของเลิกเชื่อทั้งระบบ
3. คีย์ที่เพิกถอนแล้วใช้ไม่ได้ทันที และทุกการเรียกมีร่องรอย
4. ไม่มี tool ไหนเขียนข้อมูลได้ และไม่มีฟิลด์ใน blocklist หลุดออกไปแม้แต่ตัวเดียว

- ตาราง `mcp_keys` + `mcp_call_log` + RLS + audit trigger
- ฟังก์ชัน `mcp_*` ที่ `service_role` เรียกได้ฝ่ายเดียว

- เครื่องมือ 7 ตัว อ่านอย่างเดียว
- หน้า `/mcp` (เจ้าของเท่านั้น) + กลุ่มเมนูใหม่ `เชื่อมต่อ`
- แก้ `DESIGN.md §4` + `demo.html` ให้ตรงกับเมนูที่เพิ่ม
- `docs/test-plan/P9.md` + `scripts/verify-mcp.mjs`

### ไม่ทำ (ตั้งใจตัดออก)

| ไม่ทำ | เหตุผล |
|---|---|
| tool ที่เขียนข้อมูล (อนุมัติ / บันทึกรายจ่าย) | ให้ AI กดอนุมัติแทนเจ้าของคือความเสี่ยงคนละระดับ · ถ้าจะทำต้องเป็นดีไซน์รอบใหม่ |
| OAuth | คีย์ธรรมดาก็ถูกต้องตามสเปก MCP แล้ว (Authorization เป็น OPTIONAL) และง่ายกว่ามากสำหรับคนที่ไม่ชำนาญคอม |
| `run_sql` แบบเปิด | tool ที่รับ SQL ดิบคือช่องเขียน/อ่านทุกอย่างที่ปลอมตัวเป็น tool อ่านอย่างเดียว |
| คีย์แบบจำกัดสิทธิ์รายไซต์ | ผู้ใช้ระบบมีแค่เจ้าของกับหัวหน้าไซต์ และหัวหน้าไซต์ไม่มีเหตุต้องต่อ AI — YAGNI |
| ส่งคีย์ทาง `Request headers` ในคู่มือ | รองรับที่ endpoint แต่**ไม่เขียนในคู่มือ** — ให้สองทางเลือกกับผู้ใช้ที่ไม่ชำนาญคอม = สายโทรเข้า |

## 3 · สถาปัตยกรรม

```
Claude (คลาวด์ Anthropic)  ──POST──▶  /api/mcp/<key>
                                          │ 1. ถอดคีย์ → HMAC → หาแถวใน mcp_keys
                                          │ 2. เพิกถอนแล้ว / ไม่พบ → 401 (ไม่มี WWW-Authenticate)
                                          │ 3. เกิน rate limit → 200 + isError (§5.3)
                                          │ 4. dispatch JSON-RPC
                                          ▼
                                    src/lib/mcp/*  ── admin client (service_role) ──▶  mcp_*()
                                          │                                              │
                                          │                                        SECURITY DEFINER
                                          │                                        ตั้ง request.jwt.claims
                                          │                                        แล้วเรียก RPC เดิมของแอป
                                          ▼
                                    บันทึก mcp_call_log ทุกครั้ง
```

### 3.1 ปัญหาที่ต้องแก้ก่อนอย่างอื่น

RPC เงินทุกตัวของแอป (`site_money`, `site_overview`, `site_day_wage`, `payroll_balances`)
เป็น `security invoker` และห่อทุกคอลัมน์เงินด้วย `case when public.is_owner() then …`
ซึ่งอ่าน `auth.uid()`

**service_role ไม่มี claim `sub` → `auth.uid()` เป็น null → `is_owner()` เป็น false →
ทุกคอลัมน์เงินคืน `null`** เอา RPC เดิมมาเรียกตรง ๆ จากฝั่ง MCP จึงได้ค่าว่างทั้งแผง

### 3.2 ทางแก้: มอบสิทธิ์ให้ตัวเอง**ในทรานแซกชันเดียว** แล้วเรียกของเดิม

`mcp_*` เป็น `security definer` · ตรวจก่อนว่า `p_actor` เป็นเจ้าของที่ยังใช้งานอยู่จริง
· `set_config('request.jwt.claims', json_build_object('sub', p_actor)::text, true)`
(`true` = ผูกกับทรานแซกชัน หมดอายุเองเมื่อจบคำสั่ง) · แล้ว `select … from public.site_money(...)`

```sql
create or replace function public.mcp_sites(p_actor uuid, ...)
returns table (...)
language plpgsql stable security definer set search_path = ''
as $$
begin
  if not exists (
    select 1 from public.profiles
    where id = p_actor and role = 'owner' and is_active
  ) then
    raise exception 'MCP_ACTOR_NOT_OWNER';
  end if;

  perform set_config('request.jwt.claims', json_build_object('sub', p_actor)::text, true);

  return query
    select s.id, s.name, ..., m.contract_amount, m.income_approved, m.cost_total
    from public.sites s
    join public.site_money(s.id) m on true
    ...;
end $$;

revoke execute on function public.mcp_sites(uuid, ...) from public, anon, authenticated;
grant  execute on function public.mcp_sites(uuid, ...) to service_role;
```

**ทำไมแบบนี้ ไม่ใช่คัดลอกสูตรมาวาง:** สูตรเงินอยู่ที่เดียว วันที่ใครแก้ `site_money`
ตัวเลขฝั่ง MCP เปลี่ยนตาม · ถ้าคัดลอกมา สองที่จะเพี้ยนจากกันวันแรกที่มีคนแก้ที่เดียว
เหมือนที่ `nav.ts` เตือนไว้เรื่องเมนูที่เขียนสองที่

**ทิศทางที่มันพังปลอดภัย:** ถ้า GUC ใช้ไม่ได้บน Supabase รุ่นนี้ `is_owner()` จะเป็น false
แล้วตัวเลขคืน `null` — เป็นความว่างที่**เห็นได้ทันที** ไม่ใช่ตัวเลขผิดที่ดูเหมือนถูก

**แผนสำรอง (ถ้า `verify-mcp.mjs` พบว่าไม่ทำงาน):** เขียนสูตรซ้ำใน `mcp_*` โดยคัดลอก
จาก `20260831000000_p45_wage_secrecy.sql` ตรงตัว แล้วให้สคริปต์ตรวจความเท่ากันเป็นตัวกันเพี้ยน
— สคริปต์ตัวเดียวกันครอบทั้งสองทาง จึงตัดสินใจตอนรันได้ ไม่ต้องเลือกตอนนี้

## 4 · ฐานข้อมูล

migration ใหม่ไฟล์เดียว: `supabase/migrations/20260901000000_p9_mcp.sql`

### 4.1 `mcp_keys`

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| `id` | uuid pk | |
| `label` | text not null | "โน้ตบุ๊กเจ้าของ", "ChatGPT บนมือถือ" — หนึ่งแถวต่อคน/ต่อเครื่อง |
| `key_hash` | text not null **unique** | `HMAC-SHA256(MCP_KEY_PEPPER, 'mcp-key:' + secret)` |
| `key_prefix` | text not null | 8 ตัวแรกของ secret ไว้โชว์ในตาราง (`k_3f9a21c4…`) |
| `created_by` | uuid → profiles | เจ้าของที่กดสร้าง · เป็น `p_actor` ของทุก call ที่มาด้วยคีย์นี้ |
| `created_at` / `last_used_at` / `revoked_at` | timestamptz | `revoked_at` ไม่ null = ใช้ไม่ได้ |

- 🔴 **โดเมนของ HMAC ต้องต่างจาก PIN** (`'pin-lookup:'`) และจากรหัสผ่าน — ใช้ `'mcp-key:'`
  เหตุผลเดียวกับ `CLAUDE.md` §11: ฐานข้อมูลที่รั่วต้องไม่กลายเป็นรายการคีย์พร้อมใช้
- pepper อยู่ใน env ไม่ใช่ในฐานข้อมูล
- **ไม่เก็บ secret เป็นข้อความจริงที่ไหนเลย** — โชว์ครั้งเดียวตอนสร้าง หายแล้วออกใบใหม่
- `key_prefix` = **8 ตัวแรกของ secret จริง** (ไม่ใช่ค่าสุ่มแยก) เอาไว้ให้เจ้าของชี้ได้ว่า
  ใบไหนคือใบไหน · secret ยาว 43 ตัว เปิด 8 ตัวยังเหลือให้เดาอีก 35 ตัว — วิธีเดียวกับที่ GitHub ใช้
- RLS เปิด · policy: เจ้าของเท่านั้น ทั้งอ่านและเขียน · audit trigger ติด
- 🔴 ต้อง **แก้ `public.audit_row()` ให้ตัด `key_hash` ออกเพิ่มจาก `pin_hash`**
  ไม่งั้น hash ของคีย์จะไปนอนอยู่ใน `audit_log` ซึ่งไม่มี policy ให้ลบตลอดกาล
  · นี่คือการแก้ฟังก์ชันที่**ทุกตารางใช้ร่วมกัน** — migration ต้อง `create or replace` ทั้งตัว
  และสคริปต์ตรวจต้องยืนยันว่า `pin_hash` ยังถูกตัดอยู่เหมือนเดิม ไม่ใช่ตัดอันใหม่แล้วอันเก่าหลุด

### 4.2 `mcp_call_log`

| คอลัมน์ | ชนิด |
|---|---|
| `id` uuid pk · `key_id` uuid → mcp_keys · `tool` text · `ok` boolean · `ms` int · `error` text · `at` timestamptz |

- ใช้สองหน้าที่: ร่องรอย **และ** ตัวนับ rate limit (นับในฐานข้อมูล ไม่ใช่ Map ในหน่วยความจำ
  — Vercel รันหลาย instance เหมือนที่ `rate-limit.ts` อธิบายไว้)
- RLS: เจ้าของอ่านได้ · ไม่มี policy ให้ใครแก้หรือลบ
- index: `mcp_call_log(key_id, at desc)`
- ⚠️ **ห้ามเก็บพารามิเตอร์ของ tool ลงคอลัมน์ `error` หรือที่อื่น** — คำค้นของเจ้าของ
  อาจมีชื่อลูกค้า และ log ตัวนี้เจ้าของอ่านได้แต่ลบไม่ได้

### 4.3 ฟังก์ชัน

`mcp_overview` · `mcp_sites` · `mcp_site_detail` · `mcp_transactions` ·
`mcp_pending` · `mcp_payroll` — ทั้งหมด `security definer`, `set search_path = ''`,
`revoke … from public, anon, authenticated`, `grant … to service_role`

ทุกตัวรับ `p_actor uuid` เป็นพารามิเตอร์แรกและตรวจว่าเป็นเจ้าของที่ยังใช้งานอยู่ก่อนทำอะไร

**หกฟังก์ชันต่อเจ็ด tool** — `get_metric_definitions` เป็นข้อความคงที่ที่อยู่ใน
`src/lib/mcp/` ฝั่ง TypeScript ไม่แตะฐานข้อมูล เพราะมันคือ *คำอธิบายกติกา* ไม่ใช่ *ข้อมูล*
· เก็บไว้ข้าง ๆ นิยามของ tool ทำให้คนที่แก้สูตรในหน้าเดียวกันเห็นคำอธิบายที่ต้องแก้ตาม

## 5 · Endpoint และโปรโตคอล

- `src/app/api/mcp/[key]/route.ts` — คีย์ใน path (ทางที่เขียนในคู่มือ)
- `src/app/api/mcp/route.ts` — คีย์ใน `Authorization: Bearer` (รองรับ Claude Code / Codex)
- ทั้งคู่เรียก `handleMcp(req, key)` ใน `src/lib/mcp/handler.ts` — ตรรกะอยู่ที่เดียว
- `export const runtime = 'nodejs'` (ต้องใช้ `crypto.createHmac`)
- **ไม่ลง `@modelcontextprotocol/sdk`** — มันสร้างมาให้ `req`/`res` ของ Node และลาก
  เฟรมเวิร์กเซิร์ฟเวอร์เข้ามาเพื่อ handler ที่มี POST เดียว · เขียนเอง ไม่เพิ่ม dependency

### 5.1 เมท็อดที่ต้องมี

| เมท็อด | ตอบว่าอะไร |
|---|---|
| `initialize` | **สะท้อน `protocolVersion` ที่ client ส่งมากลับไป** · `serverInfo` · `capabilities: { tools: {}, prompts: {} }` · `instructions` ที่ **ชี้ไปที่ `get_metric_definitions`** |
| `tools/list` | 7 ตัวพร้อม `inputSchema` |
| `tools/call` | ผลลัพธ์เป็น `content: [{ type: 'text', text: <JSON> }]` |
| `ping` | `{}` |
| `prompts/list` / `prompts/get` | ชุดคำถามสำเร็จรูปภาษาไทย 3 อัน |
| `resources/list` · `resources/templates/list` | **`[]` ทั้งคู่** |

🔴 `resources/*` ต้องตอบอาร์เรย์ว่าง **ไม่ใช่ `-32601`** — แอป Claude โชว์ `-32601`
เป็นข้อความแดง ทั้งที่เราไม่ได้ประกาศ capability นั้นเลย

### 5.2 กฎ HTTP ที่ผิดแล้วพังเงียบ

| กรณี | ต้องตอบ | ถ้าทำผิด |
|---|---|---|
| คีย์ผิด / ถูกเพิกถอน | **401 เปล่า ๆ ไม่มี `WWW-Authenticate`** | มี header นั้นเมื่อไหร่ = สัญญาณ "เริ่ม OAuth discovery" · client ไปหา `/.well-known/oauth-protected-resource` แล้วเจอ 404 → connector ค้างหลังปุ่ม Connect ที่กดยังไงก็ไม่ผ่าน |
| ข้อความที่ไม่มี `id` (notification) | **202 บอดี้ว่าง** | |
| `GET` | **405 + `Allow: POST`** | อย่าเปิดสตรีม SSE ที่เราไม่เคยเขียนอะไรลงไป |
| session | **ไม่ออก `Mcp-Session-Id` เลย** | stateless คือสิ่งที่ทำให้มันรอดบน serverless |
| tool ทำงานล้มเหลว | `isError: true` ใน result ของ 200 | ถ้าตอบเป็น JSON-RPC error เซสชันจะตายแทนที่โมเดลจะอธิบายให้ฟัง |

### 5.3 Rate limit

นับจาก `mcp_call_log` ต่อ `key_id`: **60 ครั้ง/นาที** และ **1,000 ครั้ง/วัน**
(ตัวเลขเป็นค่าตั้งต้นที่กันการวนลูปของโมเดล ไม่ใช่การกันคนร้าย — คนร้ายโดนกันด้วยคีย์)

**เกินแล้วตอบ `200` พร้อม `isError: true` ไม่ใช่ `429`** *(แก้ 31 ส.ค. 2569 — ฉบับแรกเขียนว่า 429)*
ตัวนับอยู่ใน `tools/call` เท่านั้น ซึ่งเป็นจุดเดียวที่โมเดลวนลูปได้ · ตอบ 429 ที่ชั้น HTTP
ทำให้ client เห็นเป็น **ข้อผิดพลาดของ connector** แล้วเจ้าของที่ไม่ชำนาญคอมอ่านว่าระบบเสีย
· ตอบเป็น `isError` ทำให้โมเดลอ่านประโยคไทย "เรียกถี่เกินไป รอสักครู่" แล้วบอกผู้ใช้เองได้
— เหตุผลเดียวกับที่ tool ที่ล้มเหลวตอบ `isError` ไม่ใช่ JSON-RPC error (§5.2)

## 6 · เครื่องมือ 7 ตัว

ทุกตัวอ่านอย่างเดียว · ทุกลิสต์มี `order` + `range` ตาม `CLAUDE.md` §7 ·
ทุกวันที่เป็น **ค.ศ. `YYYY-MM-DD`** และผูก `Asia/Bangkok`

### 6.1 `get_metric_definitions` — ไม่มีพารามิเตอร์

**ตัวที่สำคัญที่สุด และต้องถูกชี้จาก `initialize.instructions`**
คำในธุรกิจนี้เป็นของบ้านนี้ ถ้าโมเดลหาคำนิยามไม่เจอ มันจะ**เดาคำนิยามที่ฟังดูสมเหตุสมผล
แต่ผิด** แล้วเจ้าของจะตัดสินใจจากตัวเลขนั้น

ต้องอธิบายอย่างน้อย:

- `รออนุมัติ` ยัง**ไม่ถูกนับ**เป็นรายรับหรือต้นทุน · เฉพาะ `approved` เท่านั้นที่นับ
- **ต้นทุนไซต์ = รายจ่ายที่อนุมัติแล้ว + ค่าแรงที่เกิดขึ้นแล้ว** (`cost_expense + cost_wage`)
- 🔴 **เบิกล่วงหน้าและรอบจ่ายค่าแรงคือ *เงินสดออก* ไม่ใช่ *ต้นทุน*** — ต้นทุนเกิดตอนติ๊ก
  คนเข้าไซต์ (accrual) แล้ว · นับซ้ำเมื่อไหร่ต้นทุนเป็นสองเท่าทันที (`CLAUDE.md` §17 ข้อ 1)
- `กำไรคงเหลือ = ค่างานตามสัญญา − ต้นทุนที่เกิดขึ้นแล้ว` ไม่ใช่ลบด้วยเงินที่เก็บได้
- `ต้นทุนโตเร็วกว่าเงินที่เก็บได้` = `costPercent > paidPercent` (เทียบเปอร์เซ็นต์ที่ปัดแล้ว)
- `site_id = null` ในรายการ = **ส่วนกลาง** ไม่ใช่ "ยังไม่ได้เลือกไซต์"
- คนรายเดือนมี `wage_snapshot = 0` จึงเข้าต้นทุนไซต์เฉพาะส่วน OT
- 🔴 **ฐานข้อมูลเก็บปี ค.ศ. เสมอ** — ถ้าผู้ใช้พูดเป็น พ.ศ. ให้ลบ 543 ก่อนส่งเป็นพารามิเตอร์

### 6.2 `get_company_overview({ on_date? })`

จำนวนไซต์ทั้งหมด / กำลังก่อสร้าง · ค่างานรวมของไซต์ที่กำลังก่อสร้าง · ใกล้ครบกำหนด ·
เลยกำหนด · รายรับ approved · ต้นทุน approved+ค่าแรง · จำนวนและยอดที่รออนุมัติ
(`on_date` ไม่ส่ง = วันนี้ตามเวลาไทย)

### 6.3 `list_sites({ status?, limit=20, offset=0 })`

ต่อไซต์: `id`, ชื่อ, ชื่อลูกค้า, สถานะ, ค่างาน, เก็บเงินแล้ว, ต้นทุน (แยก `expense`/`wage`),
กำไรคงเหลือ, `%เก็บเงิน`, `%ต้นทุน`, ธง `overrun`, วันเริ่ม/วันจบ, วันคงเหลือ

### 6.4 `get_site_detail({ site_id })`

ตัวเลขเงินชุดเต็ม + แผนงวดเงิน (`site_milestones`) + หัวหน้าไซต์ที่ดูแล **ณ วันนี้** +
รายการล่าสุด 10 แถว + ยอดค่าแรงสะสมของไซต์

### 6.5 `search_transactions({ from?, to?, kind?, status?, site_id?, category?, q?, limit=30, offset=0 })`

- `q` ค้นใน `note` เท่านั้น · 🔴 **ต้อง escape ก่อนยัดเข้า `.or()`** —
  คอมมาในคำค้นจะกลายเป็นเงื่อนไขที่สองเงียบ ๆ (`CLAUDE.md` §7)
- คืน `id`, วันที่, ชนิด, สถานะ, ยอด, หมวด, ชื่อไซต์ (หรือ "ส่วนกลาง"), วิธีจ่าย, `note`,
  เหตุผลที่ตีกลับ, จำนวนสลิปที่แนบ (**ตัวเลขเท่านั้น ไม่ใช่คีย์หรือลิงก์**)
- คืน `total_count` มาด้วยเพื่อให้โมเดลรู้ว่ายังมีต่อ — ไม่ใช่ให้มันเดาจากจำนวนแถว

### 6.6 `get_pending_approvals({ limit=20 })`

จำนวน + ยอดรวม + รายการที่รออนุมัติ พร้อมชื่อคนที่คีย์และคีย์มากี่วันแล้ว

### 6.7 `get_payroll_summary({ limit=10 })`

- ค้างจ่ายรายคน: ชื่อ, ตำแหน่ง, ค่าแรงที่เกิดขึ้น, เบิกไปแล้ว, คงเหลือ (จาก `payroll_balances`)
- รอบจ่ายล่าสุด: ช่วงวัน, ไซต์, สถานะ, ยอดสามก้อน
- 🔴 ต้องระบุในคำอธิบาย tool ว่า **"ยอดเบิกและยอดจ่ายไม่ใช่ต้นทุน อย่าบวกเข้ากับต้นทุนไซต์"**

### 6.8 กฎที่ครอบทุก tool

- ตัวเลขเงินคืนเป็น **number ที่เป็นสตางค์ถูกต้อง** ไม่ใช่สตริงที่จัดรูปแล้ว
  (ให้โมเดลจัดรูปเอง — ตัวเลขที่มีคอมมาแล้วโมเดลบวกต่อไม่ได้)
- ถ้าตัวเลขคืน `null` ให้ตอบเป็นข้อความว่า "ไม่มีสิทธิ์เห็น" ไม่ใช่ปล่อย `null` ดิบ
  หรือแปลงเป็น 0 — 0 กับ "ไม่ได้ตั้งค่า" กับ "ห้ามดู" เป็นคนละเรื่องกัน

## 7 · ความปลอดภัย

### 7.1 Blocklist — ห้ามออกจากระบบเด็ดขาด

| ฟิลด์ | ทำไม |
|---|---|
| `sites.client_phone`, `sites.address` | ข้อมูลติดต่อลูกค้า — ไม่จำเป็นต่อคำถามเรื่องเงิน |
| อีเมลสังเคราะห์ของบัญชี PIN | ผู้ใช้ไม่เคยพิมพ์มัน รับเมลไม่ได้ และมันไม่ควรโผล่ที่ไหนเลย (`CLAUDE.md` §11) |
| `profiles.pin_hash` · `mcp_keys.key_hash` | ไม่ต้องอธิบาย |
| `attachments.object_key` / `thumb_key` / presigned URL | R2 ไม่มี RLS — ลิงก์ที่หลุดคือไฟล์ที่หลุด · คืนได้แค่ **จำนวนสลิป** |
| `push_subscriptions.*` · `upload_intents.*` | ไม่มีคำถามทางธุรกิจข้อไหนต้องใช้ |
| `app_settings.*` | เลขผู้เสียภาษี เลขบัญชีธนาคาร ผู้ลงนาม |
| `login_attempts.*` | IP ของคน |

**ที่ส่งได้:** ชื่อไซต์ · ชื่อลูกค้า · ชื่อคนงาน · ตำแหน่ง · เรตค่าแรง · ทุกตัวเลขเงิน ·
`note` ของรายการ — เจ้าของต้องใช้ชื่อเพื่อสั่งงานต่อ และคีย์นี้เป็นสิทธิ์ระดับเจ้าของอยู่แล้ว

การบังคับ: `mcp_*` **เลือกคอลัมน์เป็นรายชื่อ ห้าม `select *`** — `select *` วันนี้ปลอดภัย
แต่พรุ่งนี้ที่มีคนเพิ่มคอลัมน์ `client_email` มันจะไหลออกไปเองโดยไม่มีใครแตะไฟล์นี้

### 7.2 คีย์

- secret สุ่ม 32 ไบต์ → base64url → มี prefix `k_` ให้เห็นว่าคืออะไรตอนหลุดใน log
- โชว์ครั้งเดียวหลังสร้าง · หน้าตารางโชว์แค่ `key_prefix`
- เพิกถอนได้ทีละใบ (`revoked_at`) — ไม่ใช่ลบแถว เพราะ `mcp_call_log` ยังต้องอ้างถึง
- ถือว่า URL ที่มีคีย์ = รหัสผ่าน · หน้า `/mcp` ต้องเตือนเรื่องการแคปหน้าจอส่งต่อ

### 7.3 🔴 localhost ต่อไม่ได้ ไม่ว่าจะทำยังไง

Claude เรียกจาก**คลาวด์ของ Anthropic ไม่ใช่จากเครื่องผู้ใช้** — `http://localhost:3000/...`
ไปตกที่เครื่องของ Anthropic แล้วล้มเหลว

หน้า `/mcp` พิมพ์ URL จาก host ของ request ตัวเอง จึงต้องตรวจและ**เตือนบนหน้าจอ**
ไม่งั้นเจ้าของจะคัดลอก `localhost` ไปแล้วมาบอกว่าเซิร์ฟเวอร์เสีย:

```ts
const isLocalOrigin =
  /^https?:\/\/(localhost|127\.|0\.0\.0\.0|\[::1\]|192\.168\.|10\.|172\.(1[6-9]|2\d|3[01])\.)/
    .test(origin)
```

และ **Vercel Deployment Protection บน preview URL ตอบกำแพงล็อกอินที่ connector ผ่านไม่ได้**
— ต้องใช้ production หรือปิด protection สำหรับ deploy นั้น

### 8.1 คู่มือที่ต้องเขียนให้ตรงเป๊ะ

> ข้อเท็จจริงเหล่านี้เดาเอาไม่ได้ · **ตรวจกับ claude.ai เมื่อ 31 ส.ค. 2569**
> ถ้าลูกค้าบอกว่าเมนูไม่อยู่ตรงนี้ **ให้เชื่อลูกค้า แก้ข้อความ แล้วแก้วันที่กำกับ**

**Claude — บัญชีส่วนตัว**
`Settings → Customize → Connectors → + → Add custom connector`
🔴 ชั้น **`Customize`** คือชั้นที่ทุกคนตกหล่น และเป็นสาเหตุอันดับหนึ่งของ "หาปุ่มไม่เจอ"

`Organization settings → Connectors → Add → เอาเมาส์ชี้ Custom → Web`
**เจ้าของบัญชีองค์กรเท่านั้น** — สมาชิกธรรมดาไม่มีปุ่มนี้ หาไปก็ไม่เจอ

- แผนฟรีใช้ได้ **1 ตัว** · แผนเสียเงินได้หลายตัว (ไม่ใช่ "ต้องเสียเงินเท่านั้น")

  · ต้องบอกก่อน ไม่งั้นเจ้าของจะหาในแอปจนถอดใจ
- ช่อง **Authentication เลือก `None`** (กล่องจะขึ้น `Detected` ให้เอง) — เลือกโหมด OAuth
  แล้ว connector จะไปนั่งอยู่หลังปุ่ม Connect ที่กดยังไงก็ไม่สำเร็จ
- 🔴 **กด Add เสร็จแล้วต้องสลับ tools จาก `Needs approval` เป็น `Always allow`**
  ค่าเริ่มต้นคือถามยืนยันทุกครั้ง ซึ่งเจ้าของที่ไม่ชำนาญคอมอ่านว่าเป็น error
  — นี่คือสาเหตุอันดับหนึ่งของ "ต่อแล้วแต่ใช้ไม่ได้"

**ChatGPT**
`Settings → Connectors → Advanced → เปิด Developer mode` แล้วสร้าง connector ใหม่จาก URL เดียวกัน
พร้อมหมายเหตุว่า **เส้นทางที่เราตรวจแล้วคือฝั่ง Claude** ฝั่ง ChatGPT ให้ยึดหน้าจอจริงเป็นหลัก

## 13 · ความเสี่ยงที่รู้แล้ว

| ความเสี่ยง | รับมือ |
|---|---|
| GUC `request.jwt.claims` ใช้ไม่ได้ตามคาด | ตัวเลขจะเป็น `null` ทั้งแผง — เห็นทันทีจากแถวที่ 1 ของสคริปต์ · มีแผนสำรองคัดลอกสูตรพร้อมตัวกันเพี้ยนตัวเดียวกัน |
| คู่มือ UI ของ claude.ai ล้าสมัย | เขียนวันที่กำกับไว้ในหน้าจอ · ลูกค้าบอกว่าไม่ตรง = แก้ตามลูกค้าทันที ไม่เถียง |
| คีย์ใน URL หลุดจากการแคปหน้าจอ | เพิกถอนได้ทีละใบ · หน้าจอเตือน · มี `mcp_call_log` ให้ดูว่าถูกใช้จากไหนบ้าง |

| นับต้นทุนซ้ำระหว่างค่าแรงกับรอบจ่าย | เขียนไว้ทั้งใน definitions และในคำอธิบายของ `get_payroll_summary` |
