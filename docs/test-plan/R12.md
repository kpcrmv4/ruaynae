## 2 · สูตรคำนวณ — `R12-CALC` (เคสจากเอกสารการตัดสินใจ 9 เคส · ครบ 9/9)

**กติกาที่ถอดจากไฟล์ของเจ้าของ** — ทั้งสองใบไม่ได้คิดจากราคาต่อหน่วย
แต่คิดจาก **ยอดสุทธิที่ตกลงกัน** แล้วถอดกลับหารด้วย `1 + rate`

```
โหมด inclusive ("ยอดที่กรอกรวม VAT แล้ว"):
  gross        = Σ ROUND(qty × unit_gross, 2)          ← ยอดที่ตกลงกับลูกค้า
  unit_price   = unit_gross / (1 + rate)               ← เก็บ 4 ตำแหน่ง เหมือนที่ Excel เก็บ
  line_total   = ROUND(qty × unit_price, 2)
  subtotal     = Σ line_total                          ← บรรทัดบนกระดาษต้องบวกได้ยอดนี้เป๊ะ
  vat          = gross − subtotal                      ← 🔴 VAT เป็นตัวรับเศษ
  total        = gross                                 ← ตรงกับที่ตกลงเสมอ

โหมด exclusive ("ยอดที่กรอกยังไม่รวม VAT"):
  subtotal = Σ ROUND(qty × unit_price, 2) · vat = ROUND(subtotal × rate, 2) · total = subtotal + vat

โหมด none: vat = 0 · total = subtotal
```

🔴 **ทำไม VAT ต้องเป็นตัวรับเศษ** — ถ้าใช้ `ROUND(subtotal × 7%, 2)` กับ CM011
จะได้ 37,943.92 และยอดรวม **579,999.99** หายไปหนึ่งสตางค์จากยอดที่ตกลงไว้
Excel รอดมาได้เพราะไม่ปัดตรงกลาง แต่เราเก็บลงฐานข้อมูลต้องปัด

🔴 **สูตรนี้ถูกเขียนสองที่** (SQL `doc_recalc()` + TS `src/lib/documents.ts`)
จึงต้องขับด้วย **ตารางเคสเดียวกัน** และยืนยันว่าสองฝั่งตอบเท่ากัน ไม่ใช่เขียนเทสต์แยกสองชุด
