# P8 · ข้อมูลตัวอย่าง · เช็คลิสต์ก่อนส่งมอบ · ตรวจรับรวม

> เฟสปิดงาน — ไม่มีฟีเจอร์ใหม่ · มีสามอย่าง: ข้อมูลตัวอย่างที่เชื่อถือได้
> · เช็คลิสต์ก่อน deploy ที่ **รันได้** ไม่ใช่จำเอา · และการไล่ตารางทุกเฟสให้ปิด

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีคำสั่งรันได้รองรับ · `❌` ตก · `👤` ต้องคนตรวจ
· `⚠️` **กลไกตรวจทำงานแล้วและมันกำลังเตือนอยู่** — สคริปต์พิสูจน์ตัวเองได้ว่าจับเจอ
แต่ตัวข้อยังค้าง รอคนไปกดที่ Supabase/Vercel หรือรอไฟล์จากเจ้าของ · **ห้ามติ๊ก `✅`**
เพราะ `✅` แปลว่าเรื่องนั้นเรียบร้อยแล้ว ไม่ใช่แค่ตรวจเจอ

## สรุป

```
รวม 25 แถว
  ✅ ผ่านโดยมีคำสั่งรันได้รองรับ : 15
  ⚠️  กลไกพร้อม แต่ข้อยังค้าง     : 4   (SHIP-02 · SHIP-03 · SHIP-05 · SHIP-09b)
  👤 ต้องมีเบราว์เซอร์/เครื่องจริง : 6
  ❌ ตก                          : 0
```

**4 ข้อที่ยังค้าง ไม่ใช่บั๊ก แต่เป็นงานที่ต้องทำก่อนส่งมอบ** — `verify-ship.mjs`
พิมพ์ออกมาให้ทุกครั้งที่รัน จึงลืมไม่ได้:

| ข้อ | ต้องทำอะไร | ทำได้เมื่อไหร่ |
|---|---|---|
| SHIP-02 | เปิด Leaked Password Protection ที่ Supabase | หลังเปลี่ยนรหัสทดสอบแล้ว (ไม่งั้นล็อกอินเดโม่ไม่ได้) |
| SHIP-03 | เปลี่ยนรหัสผ่านเจ้าของและ PIN ทั้งสองใบ | ก่อนส่งมอบ |
| SHIP-05 | ตั้ง pg_cron: `sweep-orphans` รายชั่วโมง · `push-dispatch` รายนาที | หลัง deploy (ต้องมี URL สาธารณะก่อน) |
| SHIP-09b | แทนไอคอนที่ระบบวาดเองด้วยโลโก้จริง | เมื่อเจ้าของส่งไฟล์โลโก้มา |

**กฎการติ๊ก** — แถวที่ ID มี `-SEED-` `-SHIP-` ต้องมี ID อยู่ใน label ของ check
ที่รันได้จริงใน `scripts/**` · กระทบยอดด้วย `node scripts/verify-matrix.mjs`

**ทำไมแถว `👤` ถึงไม่ถูกติ๊กโดยอัตโนมัติ** — สกิล `kp-autonomous-loop` ห้าม
ลูปติ๊กแถวที่ตัวเองพิสูจน์ไม่ได้ · แถวพวกนี้ต้องมีคนเปิดเบราว์เซอร์จริง
หรือมี Playwright ที่รันได้ · การติ๊กจากความจำทำให้ตารางทั้งใบเชื่อไม่ได้
